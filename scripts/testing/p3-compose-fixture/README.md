# P3 disposable Compose fixture

This fixture runs only in the same-repository PR #384 candidate gate on a GitHub-hosted Ubuntu 24.04 job, checked out at the PR head SHA. It must never be pointed at a developer Docker context. The preparation script verifies the repository, branch, exact checkout SHA, hosted runner and private empty Docker config before starting Docker.

The preparation step builds the repository's pinned BusyBox fixture without network access, pushes it to a pinned ephemeral registry on loopback, reads the registry's manifest digest, pulls by that exact digest, then removes the registry and its dedicated preparation network before cases begin. The harness creates one run-scoped synthetic project, two owned internal networks, one owned volume and one bounded public-content service from that image. The image contains no application secrets or user data. Container CPU, memory and PID limits, run identity, exact IDs, allowed Docker operations and an overall deadline are recorded before any mutation.

The API and authenticated agent source under test perform inspection, network attach/detach, bounded volume replacement, backup and confirmed cleanup against those exact resources. Cleanup executes through the signed API-to-agent transport and removes only the confirmed resource after fresh inspection shows no consumers. A `finally` path verifies exact resources are absent; failures preserve evidence and fail the job. No wildcard cleanup, shared Docker context, host port publication by the tested service or production target is permitted. The registry's loopback port exists only during pinned fixture preparation and is removed before the product cases.

The evidence artifact binds the repository, ref, exact head commit, workflow run/attempt, disposable engine, fixture source hashes, operation receipts and cleanup readback. The P3 acceptance gate remains isolated from the general baseline-gate dependency set. The existing P2 Docker gate is unchanged and does not count toward P3 acceptance.
