## Adapter and reuse decisions

- Run 37972106056 on docs-only head `0a086d0` failed the quality `pnpm test` step; its precise assertion remains unknown. The subsequent full run 37974541187 at `f93a9fd` passed all six gates, including quality, PostgreSQL, compose/supply-chain, P2, P3, and baseline-gate, so the current branch gate for L3 is green without inferring the old failure's cause.
- L4 foundation: strict versioned TCP/UDP publication contracts, a pure planner keyed by `(protocol, publishedPort)`, and a global PostgreSQL claim table/reader are implemented. Same-number TCP and UDP claims are independent; an occupied same-protocol port conflicts globally; identical project/deployment/target repeats are no-ops; same-project changes retain the prior target for rollback planning. Node 24.20.0 builds and tests pass: contracts 156/156, domain 440/440, DB 165 passed/74 existing integration tests skipped. `pnpm db:check` validates all 24 migration files. No local database connection/migration, Docker, Traefik, host port, firewall, registry, or deployment operation was run.
- The transport-port API exposes a read-only project preview guarded by `project.deploy`, a same-project successful deployment with a matching trusted execution receipt, global claim lookup, planner conflict checks, and mandatory correlated audit. The nine focused preview cases pass; the API suite passes 633 tests with 26 existing skips, the transport claim reader passes 3 tests, and the transport planner passes 8 tests. Domain/DB builds and API source typecheck pass on Node 24.20.0. The preview does not reserve a claim or inspect host socket availability; apply/rollback remains separate work.
- L4 local apply/rollback increment: PostgreSQL persists protocol/port reservations, redacted route revisions, and each deployment's last verified container ID and complete port-binding set. The API requires `project.update`, a matching trusted image receipt, idempotency, a durable reservation, agent receipt validation, and atomic command/claim/revision/runtime-state/audit completion. The authenticated agent preflights the digest-pinned image on an ephemeral loopback port, replaces only the trusted container, verifies final bindings/network/health, and restores the exact prior container on a port conflict or failed cutover. A PostgreSQL test covers apply, retarget, rollback, replay, reservation release, audit, and active-container state; it is included in the opt-in disposable-DB suite and was skipped locally. Full `pnpm check` passed with Node 24.20.0: build, lint, typecheck, 2,301 tests passed and 102 opt-in PostgreSQL/Docker cases skipped. `db:check` validated all 25 migrations. No local PostgreSQL, Docker, or migration operation ran; hosted CI is still required for the PostgreSQL case.
- Boundary still open: same-deployment port edits and rollback are covered; cross-deployment ownership changes currently fail closed because a safe move must coordinate both deployment containers and their other published bindings. Registry pull/credential behavior and the integrated exact-source L5 acceptance are also still open. P4 remains at 70% (7/10 fully evidenced criteria); criterion 9 is partial and receives no completion credit yet.
- For raw TCP/UDP, follow Dokploy's separate Advanced → Ports model: an explicit published host port maps to a target container port and protocol and is reached as `host:port`; it is distinct from hostname/Traefik domain routing. Keep HTTP/WebSocket/TLS on the watched file provider. Transport port edits must use DeployLite's authorized execution and rollback path; do not reserve a broad public port range. Reference: [Dokploy Applications: Advanced settings and Ports](https://docs.dokploy.com/docs/core/applications/advanced).

- Selected adapter: follow Dokploy's standalone Applications pattern—Traefik's watched file provider with generated dynamic configuration and hot reload. Dokploy uses labels plus redeployment for Compose services; those labels are not the right update path for an already-running standalone application. References: [Dokploy Domains](https://docs.dokploy.com/docs/core/domains), [Dokploy Domains and Traefik troubleshooting](https://docs.dokploy.com/docs/core/troubleshooting/domains).
- PostgreSQL already has `domains` and `certificates` linked by `domain_id`; keep these relations and do not create duplicate domain or certificate tables.
- Existing project image receipts and digest policy provide the registry trust foundation; L4 still needs to preserve that boundary while adding registry behavior.
- A P4 host claim conflicts with any existing hostname row, even if that row has no application deployment target. Shared route networking is not used because it would allow cross-project app traffic; route targets use project-isolated networking.
- L3 implementation is published on `feat/p4-route-policy` at `ba5cb6d`; exact-source run 37970129129 passed. PR #387 remains a draft and is not merged to protected main. The protected-main checkout, other projects, and external runtime configuration are outside this delivery.
