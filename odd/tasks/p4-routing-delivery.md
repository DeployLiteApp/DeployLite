- L4 local cross-deployment increment: the versioned transfer capability carries a trusted source execution receipt, source deployment/container identity, and before/after bindings. The API checks that source and target are successful same-project deployments on the same agent, validates the persisted source container/bindings, and binds the transfer to the command digest. The agent preflights both services on loopback, checks both exact prior binding sets, parks both trusted originals, verifies both replacements, and attempts to restore both exact originals if cutover fails. PostgreSQL completion updates source and target claims/runtime rows and shared command/revision/audit evidence atomically. Focused API/agent tests cover successful transfer, stale or mismatched source rejection, capability negotiation, and restoration after second-container failure. The PostgreSQL transfer/rollback integration test remains opt-in and was skipped locally; no local DB, Docker, or migration execution ran. `pnpm check` with Node 24.20.0 passed; `db:check` with Node 24.20.0 validated all 27 migrations.
- Boundary still open: registry trust/credential behavior and integrated exact-source L5 acceptance remain. The new cross-deployment path has local evidence but still needs its disposable hosted PostgreSQL gate and full acceptance. P4 remains at 70% (7/10 fully evidenced criteria); criterion 9 is partial and receives no completion credit yet.
- For raw TCP/UDP, follow Dokploy's separate Advanced → Ports model: an explicit published host port maps to a target container port and protocol and is reached as `host:port`; it is distinct from hostname/Traefik domain routing. Keep HTTP/WebSocket/TLS on the watched file provider. Transport port edits must use DeployLite's authorized execution and rollback path; do not reserve a broad public port range. Reference: [Dokploy Applications: Advanced settings and Ports](https://docs.dokploy.com/docs/core/applications/advanced).

- Selected adapter: follow Dokploy's standalone Applications pattern—Traefik's watched file provider with generated dynamic configuration and hot reload. Dokploy uses labels plus redeployment for Compose services; those labels are not the right update path for an already-running standalone application. References: [Dokploy Domains](https://docs.dokploy.com/docs/core/domains), [Dokploy Domains and Traefik troubleshooting](https://docs.dokploy.com/docs/core/troubleshooting/domains).
- PostgreSQL already has `domains` and `certificates` linked by `domain_id`; keep these relations and do not create duplicate domain or certificate tables.
- Existing project image receipts and digest policy provide the registry trust foundation; L4 still needs to preserve that boundary while adding registry behavior.
- A P4 host claim conflicts with any existing hostname row, even if that row has no application deployment target. Shared route networking is not used because it would allow cross-project app traffic; route targets use project-isolated networking.
- L3 implementation is published on `feat/p4-route-policy` at `ba5cb6d`; exact-source run 37970129129 passed. PR #387 remains a draft and is not merged to protected main. The protected-main checkout, other projects, and external runtime configuration are outside this delivery.
